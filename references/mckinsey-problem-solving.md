# 麦肯锡式问题解决工作法

本参考把常用的结构化问题解决原则转化为员工访谈分析规则，不声称复刻任何机构的内部专有流程。

## 1. 定义问题

明确决策者、需要作出的决定、成功标准、分析边界、时间范围和关键约束。把宽泛任务改写为：哪些现象影响业务或员工体验，可能由哪些机制导致，现有证据支持到什么程度，管理层现在应处理、验证还是观察什么？

## 2. 提取现象

用“对象—行为或事件—情境—后果”表达现象。现象不得包含未经验证的归因。例如，把“领导不重视协同”改为“多个项目在执行开始后才收到关键决策信息，并发生返工”。

## 3. 建立议题树

围绕管理决策拆解“需要知道什么”，优先按机制而非访谈题目分类。检查同层分支是否尽量不重复、关键解释是否遗漏、粒度是否相近、能否被证据验证。员工材料天然交叉时标明主分支和关联项，不得为形式上的 MECE 扭曲事实。

## 4. 假设驱动

对高价值议题提出主要解释、至少一个合理的竞争性解释、支持或削弱各解释的证据，以及当前缺失信息。优先验证最可能改变决策的假设，禁止用假设筛掉反向证据。

## 5. 80/20 聚焦

优先级由决策影响、风险紧迫度、覆盖度、后果强度、证据置信度和可控性共同决定。不能只按提及次数排序；孤立但严重的安全或伦理信号应优先路由。

## 6. 综合与表达

每项结论回答：发生了什么、为何重要、哪个组织机制可能参与、还有哪些合理解释、管理层需要决定什么。正式报告按金字塔结构先呈现结论和待决事项，再列互不重复的关键论据，最后给出证据、反证、方法与限制。标题使用结论句，不只写“沟通”“激励”等话题词。
