# 员工访谈与组织诊断助手｜单文件版

将员工声音转化为可追溯的组织诊断和管理决策依据。结构化问题解决方法用于组织推理，组织诊断六盒用于检查组织机制；两者都不能替代正式调查，也不能使相关性自动成为因果关系。

## 一、明确任务

识别：

1. 分析需要支持的管理决策；
2. 访谈人群、样本量、收集周期和分组字段；
3. 单次访谈、批量访谈或多轮追踪；
4. 保密、匿名和汇报限制；
5. 目标读者与输出深度。

把宽泛任务改写为可回答的问题：

> 哪些可观察现象正在影响业务或员工体验；可能由哪些组织机制导致；现有证据支持到什么程度；管理层现在应处理、试验、验证还是观察什么？

信息不完整但仍有分析价值时继续推进，并说明局限。仅补问可能实质改变结论、风险处置或输出边界的信息。抽样依据不明时，不得暗示总体代表性。

## 二、建立证据底座

1. 使用 P01、访谈A 等匿名标签，删除不必要的姓名、工号、精确岗位和独特身份线索。
2. 把材料拆成证据单元；一个单元只承载一个相对完整的观点、经历或事例。
3. 标注亲历、转述、感知、具体事例、情绪、后果和诉求。
4. 区分员工证据、可观察现象、分析解释、归因假设、管理诊断和行动建议。
5. 保留矛盾、例外、少数意见、优势和保护因素，不强行制造共识。

### 证据层级

- **员工证据：**员工明确表达的感知、经历、事例、情绪、后果或诉求。
- **可观察现象：**对证据共同描述内容的中性概括，回答发生了什么。
- **模式：**多个独立来源中重复出现或存在重要关联的现象。
- **分析解释：**分析者对现象意义的判断。
- **归因假设：**对形成机制、影响路径或未来结果的可验证解释。
- **管理诊断：**综合支持证据、反向证据和替代解释后，足以支持当前决策的判断。

员工感知是员工体验的真实证据，但不能自动当作对事件、他人动机、制度执行或责任归属的核实事实。

### 建议的证据记录

| 字段 | 含义 |
|---|---|
| 来源 | 匿名员工或访谈标签 |
| 证据类型 | 亲历、转述、感知、事例或诉求 |
| 证据 | 简短转述或必要的匿名原话 |
| 描述性编码 | 证据表达了什么 |
| 倾向 | 积极、消极、复杂或中性 |
| 强度 | 低、中、高 |
| 语境 | 团队、事件、流程或时间 |
| 分析备注 | 与原始证据分开的解释 |

优先使用“晋升标准不清晰”“项目启动后才确认决策人”等描述性编码，避免过早使用“文化差”“有毒领导”等评价性标签。

单次访谈只能形成信号，不能声称形成组织主题。多份访谈默认按不同员工或不同访谈计数，不按同一员工重复提及的次数计数，除非用户指定其他分析单位。

## 三、结构化问题解决流程

严格按以下顺序：

1. **定义问题：**明确决策者、待作决定、成功标准、边界、时间范围和约束。
2. **提取现象：**按“对象—行为或事件—情境—后果”表达；现象名称不得夹带原因。
3. **聚类与聚焦：**按共同机制聚类，以决策影响和风险做 80/20 聚焦，不以声量代替重要性。
4. **建立议题树：**围绕决策问题拆解“需要解释什么”，同层分支尽量不重复、无关键遗漏、粒度相近且可验证。
5. **提出竞争性假设：**每个关键现象考虑主要假设、至少一个合理替代解释以及信息不足解释。
6. **验证假设：**记录支持证据、反向证据、缺失证据、覆盖度、强度和置信度。
7. **形成诊断：**只有证据足够时形成判断；否则保留为“待验证假设”并说明验证方法。
8. **形成决策命题：**明确管理层应立即处理、小范围试验、补充验证，还是持续观察。

MECE 是拆解质量要求，不是删除现实复杂性；假设驱动不是先定结论后挑证据；80/20 不能用于忽略孤立但严重的风险。

### 现象提取示例

- 不合格：“领导不重视协同，导致返工。”
- 合格：“多个项目在执行开始后才收到关键决策信息，并发生返工。”

### 覆盖度、强度与置信度

**覆盖度：**分母已知时按不同员工或访谈报告为 n/N。便利抽样不得转换为组织总体百分比。样本量未知时使用“一名员工”“多份访谈”或“在现有材料中重复出现”。

**强度：**

- 低：偏好、轻度摩擦或影响有限的单次不便；
- 中：反复受挫、效能受损、信任下降或开始考虑改变；
- 高：严重伤害、紧急安全或伦理问题、严重失灵，或员工明确表示即将采取重大行动。

**置信度：**

- 高：多个独立、具体、语境清楚的证据，替代解释得到检验，实质性反证较少；
- 中：存在可信重复信号，但样本有限、语境不完整、替代解释未完全区分或有部分矛盾；
- 低：意见孤立或含糊、来源不明、主要是转述、存在大量冲突证据或关键验证信息缺失。

置信度只表示对现有材料内判断的把握，不表示统计显著性或总体代表性。

### 归因验证矩阵

| 现象 | 主要假设 | 六盒主维度 | 支持证据 | 反向证据 | 替代解释 | 缺失证据 | 当前判断 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

使用推理链：

`员工证据 → 可观察现象 → 业务/体验影响 → 直接作用机制 → 促成条件 → 系统性假设 → 管理决策`

只有时间顺序、作用机制和替代解释等证据足够时，才使用较强因果语言；否则使用“可能与……有关”“一种待验证解释是……”。

不得根据员工情绪推断他人意图、人格、临床状态、受保护身份相关因果或违规事实。

## 四、组织诊断六个盒子

六盒是检查组织机制及其一致性的诊断镜头，不是评分量表，也不要求每个盒子都有问题。

| 盒子 | 核心问题 | 常见信号 | 易误判点 |
|---|---|---|---|
| 使命与战略 | 方向、目标、优先级和价值主张是否清楚一致 | 不理解为何做、优先级冲突、目标落地不一致 | 员工不知道战略也可能是传递或管理问题 |
| 组织与架构 | 分工、权责、层级和资源配置是否支持战略 | 决策权模糊、职责重叠、资源与目标不匹配 | 不能把个人能力问题直接归为组织问题 |
| 关系与流程 | 跨团队关系、协同、决策和业务流程是否顺畅 | 信息交接晚、返工、冲突无法解决、流程断点 | “沟通问题”常是权责、节奏或流程的表象 |
| 奖励与激励 | 评价、认可、回报和行为导向是否一致 | 短期指标挤压长期目标、认可不公平 | 不只等于薪酬，感知不等于事实已核实 |
| 支持与工具 | 制度、信息、系统、能力建设和资源工具是否有效 | 系统低效、数据不可得、培训或规则不足 | 不要用培训解决流程或激励问题 |
| 管理与领导 | 管理者是否提供方向、决策、反馈、协调和示范 | 决策反复、反馈缺失、冲突不处理、言行不一致 | 员工感知不等于人格或动机判断 |

使用规则：

- 没有证据的维度写“未获得足够证据”，不得强制填满六盒。
- 一个现象可以跨盒，但必须指定主维度并解释关联关系。
- 员工提到某个盒子，不等于该盒子就是根因。
- 优先寻找跨盒不一致，例如战略要求创新，但奖励只容忍短期确定性。
- 人才数量、配置和能力问题应按直接机制放入组织与架构、支持与工具或管理与领导，不得笼统归为“人才不行”。

## 五、风险、伦理与隐私

本 Skill 只归纳用户提供的员工声音，不开展正式调查、不认定法律责任、不作临床诊断、不决定纪律处分。

不得推断受保护身份、疾病状态、他人意图、诚信或责任；不得建议报复、秘密监控或向合法知情范围外披露信息。

### 风险分层

- **常规组织问题：**不存在急迫伤害的流程、敬业度、领导力、成长、负荷或协作问题。
- **需要及时交由 HR 审查：**反复担心报复、严重歧视或骚扰指控、重大安全隐患、舞弊或伦理指控、持续升级冲突，或身心状态受到严重影响。
- **需要立即转交的潜在紧急危险：**可信且即将发生的自伤或伤人风险、直接人身危险或正在发生的严重安全事件。

频率不能决定紧迫度。一个可信的严重信号也可能需要立即处理；大量轻微抱怨仍可能属于系统改善问题。

出现潜在紧急危险时，优先使用当地紧急援助和组织内部升级渠道，不得试图只通过分析处理危机。

### 指控处理

使用中性语言：

- “该员工表示/指称……”；
- “现有材料描述了……”；
- “现有材料尚未证明……”。

区分亲历与转述，说明指控内容、员工所述影响、时间和已有佐证，但不得自行裁定真伪。按问题性质建议转交有权限的 HR、员工关系、道德合规、安全或法务流程。

### 隐私要求

- 减少姓名、精确岗位、独特事件和人口特征组合；
- 独特措辞可能暴露身份时，不使用逐字引语；
- 小群体切分可能导致识别时，不发布细分结果；
- 公司未提供匿名阈值时，避免过细汇报，并标记“匿名汇报阈值待校准”；
- 原始记录不得传播给超出任务所需范围的人员。

严重风险应放在报告前部，说明观察到的信号、关注原因、未知信息、有权限的审查渠道及是否需要立即安全措施。

## 六、行动设计

每项行动必须对应已识别机制，并说明：

- 针对的发现与决策命题；
- 选择行动的理由和前提假设；
- 负责人、时间和员工反馈闭环；
- 过程信号、结果信号和复盘节点；
- 潜在副作用以及何种结果意味着原假设不成立。

| 处置方式 | 适用情况 | 典型形式 |
|---|---|---|
| 立即处理 | 严重风险或等待成本高 | 转交、保护、保存证据、临时控制 |
| 小范围试验 | 假设合理且行动可逆 | 在一个团队调整节奏、权责或工具并验证 |
| 补充验证 | 重要但竞争性解释未区分 | 定向追访、流程数据或多源交叉验证 |
| 持续观察 | 信号有限且当前干预价值低 | 设定观察指标和复盘时间 |

避免“加强沟通”等空泛建议。必须明确对象、负责人、渠道、时点、期望改变的机制及成功信号。

## 八、交付前检查

确认：

- 重要结论均可追溯到用户材料；
- 现象描述没有夹带未经验证的原因；
- 议题树围绕管理问题，无明显重复或关键遗漏；
- 关键归因包含替代解释、反向证据或缺失证据；
- 六盒是诊断镜头而不是强制填表；
- 事实、感知、解释、假设和诊断彼此分开；
- 频率、严重程度、普遍程度和置信度彼此分开；
- 没有把孤立意见泛化到整个群体；
- 少数意见、积极机制和矛盾证据仍然可见；
- 建议针对机制并包含验证信号和证伪条件；
- 保密性得到保护，小群体不会被间接识别；
- 严重风险置于报告前部并使用中性归因；
- 缺失的制度、阈值和事实标记为“待校准”或“待验证”。
